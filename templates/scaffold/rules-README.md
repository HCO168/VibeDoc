# 规则

这里放**你希望系统怎么做**的规则，一个模块一个文件（`<模块>.md`，模块名见 `vibedoc.config.json` 的 `modules` 或 `modulesFile`），文件里按四层分章节，每条规则一个 `###` 标题：

```markdown
# 应用（app）

## 前端

## API

### 登录失败五次后锁定十分钟
<!-- rule:app-1 status=new date=2026-10-29 -->
> <!--rule-badge--> ⚪ **新提出** · `app-1` · 2026-10-29

锁定期间仍可通过邮件找回密码。

## 后端

## 数据库
```

## 怎么写

- 推荐在 VibeDoc 里写：在仓库里运行 `vibedoc serve`（或打开 VibeDoc App），点「新建规则」；启用代码地图时也可以在「代码地图」里对某个接口、函数或表点「提要求」。
- 也可以直接用编辑器写：在对应层下加 `### 标题` 和正文即可。看板运行时会自动补上编号和状态行；没运行时，下次运行 `vibedoc rules refresh` 或打开看板时补上。
- 标题下面的两行（`<!-- rule:... -->` 和 `> <!--rule-badge-->`）是状态行，由工具维护，不用手改。

## 状态

| 状态 | 含义 | 谁改 |
| --- | --- | --- |
| ⚪ 新提出 | 还没处理 | 你新写的规则 |
| 🟣 待你确认 | AI 已在对话里给出执行计划 | AI；你在看板点「确认计划，开始做」或「退回」 |
| 🔵 进行中 | AI 正在实现 | AI |
| 🟠 已修改 | AI 处理过之后你又改了原文 | 自动：原文与 AI 上次处理时不一致 |
| 🟢 已实现 | 已落实到代码 | AI |
| ⏸ 搁置 | 暂时不做 | 你，在看板拖动或点「搁置／恢复」 |

## AI 怎么执行

AI 不会自动执行规则。你在对话里说「同步规则 app-1」（看板里「复制同步指令」）或「同步 app 的规则」，AI 才会：读取规则（已修改的会对比上次处理时的原文）→ 在对话里给计划并标为「待你确认」→ 你确认后标为「进行中」并改代码 → 完成后标为「已实现」。

AI 只能通过 `vibedoc rules` 命令修改状态行，不能改你写的标题和正文；工具会拒绝任何改动原文的写入。
