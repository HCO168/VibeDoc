# 功能与架构文档

这里按模块描述 **这个项目有哪些功能、整体怎么组成**，不写代码细节（函数、接口路径、表名、字段）。一个模块一个文件 `<模块>.md`，模块名见 `vibedoc.config.json` 的 `modules` 或 `modulesFile`。

- AI 负责撰写和维护正文，并标注每条功能的状态。
- 你可以像编辑文档一样直接修改整篇（编辑器，或 VibeDoc「功能文档」页的「编辑文档」，双击正文也可进入）。改过的条目自动变成「已修改」，等你让 AI 同步后才会动代码。看板保存整篇时按标题保留每条功能的编号和状态；改了标题的功能按它在本分组里的位置保留原状态，新写的 `###` 成为「新提出」，删掉的条目随之删除。文档在你编辑期间被别处（例如 AI）改过时，看板拒绝覆盖。
- 新功能在 VibeDoc「功能文档」页点「提新功能」，或直接在文件里加一个 `###` 条目。

## 格式

```markdown
# 应用（app）

> 功能与架构文档：……

模块概述与架构：由哪些部分组成、数据放在哪里、与其他模块的关系。

## 分享

### 分享链接
<!-- feature:app-f3 status=done h=... date=2026-11-03 -->
> <!--feature-badge--> 🟢 **已持久化** · `app-f3` · 2026-11-03

用户可以把内容生成分享链接，可设查看或编辑权限……
```

- `#` 标题下、第一个 `##` 之前是模块概述与架构，不跟踪状态。
- `##` 是功能分组，名字自由；「待规划」放刚提出、还没整理的功能。
- 每条功能一个 `###` 标题。标题下的两行（`<!-- feature:... -->` 和 `> <!--feature-badge-->`）是状态行，由工具维护，不用手改。

## 状态

| 状态 | 含义 | 谁改 |
| --- | --- | --- |
| ⚪ 新提出 | 还没处理 | 你提的新功能 |
| 🟣 待你确认 | AI 已在对话里给出计划 | AI；你在看板点「确认计划，开始做」或「退回」 |
| 🔵 开发中 | AI 正在实现 | AI |
| 🟢 已持久化 | 代码已合入开发主分支 | AI |
| 🚀 已上线 | 已发布到正式站 | AI（发布后） |
| 🟠 已修改 | AI 记录过之后你又改了内容 | 自动：内容与 AI 上次记录时不一致 |
| ⏸ 搁置 | 暂时不做 | 你，在看板点「搁置／恢复」 |

## AI 怎么维护

- 你说「同步功能 app-f3」或「同步 app 的功能」时，AI 用 `vibedoc features list|show` 读取待处理条目（已修改的会对比上次记录时的内容），把需求整理进文档正文、在对话里给计划并标为「待你确认」，你确认后标为「开发中」并实现，合入开发主分支后标为「已持久化」，正式发布后标为「已上线」。
- 正文由 AI 撰写；AI 每次改写正文后都用 `vibedoc features set <状态> <id>` 记录当前内容，因此只有你的修改会显示为「已修改」。AI 不会改写你改过但尚未同步的条目。
- 实现完其他任务、功能已经变化时，AI 顺手更新对应条目并记录状态。
- `vibedoc features summary` 汇总各模块的已上线、已持久化、开发中和待处理数量。
