# 数据库表变更

这里记录 **你要新建或修改的数据库表**：表名、所属 schema、字段、类型、约束和说明。AI 按条目写迁移，并标注每条的状态。一个 schema 一个文件 `<schema>.md`。

- 在 VibeDoc「代码地图 → 数据库」里点「新建表」，或在已有表的那一行点「改表」，用表单填写；表单旁实时显示 `CREATE TABLE`／`ALTER TABLE` 草稿。
- 也可以直接在文件里写，格式见下。改过的条目自动变成「已修改」，等你让 AI 同步。
- 条目只描述要什么，迁移由 AI 按仓库约定写（放在哪个目录、权限、索引、RLS 等）。

## 格式

```markdown
# billing

## 新建表

### invoices
<!-- table:billing-t1 status=new date=2026-11-03 -->
> <!--table-badge--> ⚪ **新提出** · `billing-t1` · 2026-11-03

发票，每次结算生成一张。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | uuid | 主键，默认 gen_random_uuid() |  |
| user_id | uuid | 非空，→ public.users(id)，级联删除 | 所属用户 |
| amount | numeric(12,2) | 非空，check (amount >= 0) | 金额 |

按 user_id 建索引。

## 修改表

### invoices
<!-- table:billing-t2 status=new date=2026-11-05 -->
> <!--table-badge--> ⚪ **新提出** · `billing-t2` · 2026-11-05

记录支付时间。

| 操作 | 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| 新增 | paid_at | timestamptz |  | 支付时间 |
| 修改 | amount | numeric(14,2) | 可空 |  |
| 删除 | legacy_flag |  |  | 不再使用 |
```

- `## 新建表` 和 `## 修改表` 两个分组；每条一个 `###`，标题就是表名。标题下的两行状态由工具维护，不用手改。
- 字段表前面的文字是这张表（或这次改动）的说明，字段表后面的文字是其他要求。
- 约束用中文逗号分隔：`主键`、`非空`、`可空`（修改时去掉非空）、`唯一`、`默认 <表达式>`、`→ schema.表(字段)`（字段省略时为 `id`）、`级联删除`、`删除时置空`；其他写法（如 `check (...)`）原样进入 SQL 草稿。
- 修改表时「操作」是 `新增`、`修改` 或 `删除`；修改只写要变的部分，类型留空表示不变。

## 状态

| 状态 | 含义 | 谁改 |
| --- | --- | --- |
| ⚪ 新提出 | 还没处理 | 你提的条目 |
| 🟣 待你确认 | AI 已在对话里给出迁移计划 | AI；你在看板点「确认计划，开始做」或「退回」 |
| 🔵 开发中 | AI 正在写迁移 | AI |
| 🟢 已持久化 | 迁移已写好并合入开发主分支 | AI |
| 🟠 已修改 | AI 记录过之后你又改了内容 | 自动：内容与 AI 上次记录时不一致 |
| ⏸ 搁置 | 暂时不做 | 你，在看板点「搁置／恢复」 |

还没被 AI 处理（新提出或搁置）的条目可以在看板里删除。迁移里已经能找到条目要的表或字段时，看板会在条目旁标「迁移里已有」。

## AI 怎么处理

- 你说「同步表 billing-t1」或「同步 billing 的表」时，AI 用 `vibedoc tables list|show` 读取条目（`show` 带 SQL 草稿和迁移目录；已修改的会对比上次记录时的内容），按仓库约定在对话里给出迁移计划并标为「待你确认」，你确认后标为「开发中」并写迁移，合入开发主分支后标为「已持久化」。
- AI 每次改状态都用 `vibedoc tables set <状态> <id>`，同时记录当前内容为已处理，所以只有你的修改会显示为「已修改」。
